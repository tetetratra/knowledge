- **Javaメモ**
- **ラムダ系**
  - 引数の型も返り値の型も推論してくれる
  - `( 引数 ) -> { 処理; };`だけどわかる所は色々省略できる
  - [Java のラムダ式と StreamAPI。入門レベルを図解で | コード７区](http://ailaby.com/java_lambda/)
  - 関数インターフェースとは
    - インターフェースに抽象メソッドを1つだけ定義したもの
  - filterとかでinterfaceをnewしたものを渡しているようにみえるのは、そうじゃなくて、そのinterfaceを実装した無名クラスをnewしているだけ
    - で、最近のjavaだとそれをラムダ式で書ける
    - 関数インタフェースを受ける場所でラムダ式が使用可能
    - ラムダ式を受け取るメソッドの引数の変数の型はわかっている。そしてその型は関数インターフェース。なのでメソッドも確定できる。なので引数と返り値の型も確定できる。なのでラムダ式には型を書かなくて良い。
  - filter に渡す引数は Predicate という関数型インターフェース(の無名クラスのインスタンス)と決まっている
  - streamにも色々型があって、汎用の`Stream<T>`や固有の`IntStream`とかがある
    - 固有の方はsumメソッドとかが使える
    - mapToIntというメソッドで変換する。これにも関数インターフェースをわたす(ToIntFunctionインターフェース)
  - filter実装する側の立場になると、、、
    - Predicateインターフェースを定義しておく。testメソッドを実装するように指定しておく。
    - filterの引数の型を、Predicateインターフェースを実装したクラスに指定する
    - 引数のクラスのtestメソッド(Predicateインターフェースのクラスなので絶対実装されている)で、各要素を判定する。
  - `collect(Collectors.toList())`で、streamをListに戻せる
  - forEachは、Consumer関数インターフェースと決まっている。
  - 関数型インターフェースになる条件

- **オブジェクト指向系**
  - インターフェースとは
    - 変数とメソッドの型だけを指定したもの
    - 定数とメソッドのみ書ける
      - 定数は代入がされていなければいけない
      - `String methodName(String s);`のようにメソッドは定義する
        - `public abstract`(抽象メソッド)が自動で付く
    - `interface InterFaceName`
    - `class ClassName implements InterFaceName`
      - 複数実装してOK
  - 抽象クラス
    - `abstract class ClassName`
    - クラス内に抽象メソッドを書く
    - `abstract int methodName(int hoge);`
    - `extends`で普通のクラスと同じように継承
  - オーバーロード
    - 親のメソッド再定義
  - オーバーライド
    - 引数が違えば何個も同名メソッドOK。多重定義
  - `protected`
    - 継承された子でもその変数使える
      - privateな変数は継承先の子では使えない
  - `super.methodName();`で、明示的に親のメソッドを呼べる
    - 親と子で両方定義されてるメソッドがあるときに使える。
  - コンストラクタの`super()`は自動で呼ばれる。
  - コンストラクタの1行目に`super(hoge)`のように引数を指定して書くと、親のオーバーロードされたコンストラクタから選んで実行できる
    - その場合デフォルトの親のコンストラクタは呼ばれない
  - `ParentClass a = new ChildClass();`のような書き方ができる。
    - 子クラスにしか無いメソッドは呼べなくなる
    - 子クラスでオーバーロードされたメソッドは呼べるしオーバーロードされたものが呼ばれる

- **修飾子**
  - フィールドの修飾子について
    - [Javaの文法 - Wikipedia](https://ja.wikipedia.org/wiki/Java%E3%81%AE%E6%96%87%E6%B3%95#%E6%96%87%E5%AD%97%E5%88%97)
    - `final`
    - `static`
    - `transient`
      - >オブジェクトの中でも永続的 (persistent) にできないフィールドである。このフィールドの中身を待避または復元してはならないことをコンパイラに知らせる。
    - `volatile`
      - >そのフィールドが他スレッドによって非同期にアクセスされる可能性があることをコンパイラに知らせる。finalにはなれない。
  - クラス定義に`static{ ~~~ }`と書くと、staticな変数の初期化に使える。クラスがロードされた後で実行される
    - [Javaの文法 - Wikipedia](https://ja.wikipedia.org/wiki/Java%E3%81%AE%E6%96%87%E6%B3%95#%E6%96%87%E5%AD%97%E5%88%97)
    - >「スタティックイニシャライザ」（静的初期化子）はstaticフィールドのイニシャライザと同時に実行されるコードのブロックである。静的フィールド初期化子と静的初期化子は宣言された順番に実行される。静的初期化はクラスがロードされた後で実行される。
  - メソッドの修飾子
    - [Javaの文法 - Wikipedia](https://ja.wikipedia.org/wiki/Java%E3%81%AE%E6%96%87%E6%B3%95#%E6%96%87%E5%AD%97%E5%88%97)
    - `abstract`
    - `final`
      - サブクラスで再定義不可にする
    - `native`
      - >このメソッドはネイティブなマシン依存コードにリンクする。メソッド本体無しで宣言される。abstractと併用はできない。Java Native Interfaceにて使用される。
      - よくわからぬ
    - `static`
    - `strictfp`
      - >メソッドとそこに含まれる内部クラス全てにおける浮動小数点演算が、厳密な浮動小数点演算動作を使用する。厳密な浮動小数点演算動作は、演算結果がプラットフォームに関わりなく同一となることを保証する。
    - `synchronized`
      - >メソッド本体を実行する前に、関連オブジェクトを排他する。関連オブジェクトが他スレッドにて排他済である場合、他スレッドが排他を解除し自スレッドが排他を獲得するまで実行を待たされる。ここで言う関連オブジェクトとは、そのメソッドがstaticならばClassオブジェクトを指し、非staticならばオブジェクトインスタンスを指す。abstractメソッドをsynchronizedとして宣言することは可能だが意味はない。何故なら排他とは宣言ではなく実装に伴う機能であり、抽象メソッドは実装を持たないからである。

- **Observerパターン**
  - `Observable`クラス
    - 監視される側が継承する
    - `addObserver(Observer o)`
      - observerを登録する
      - observer側からこのメソッドを呼び出す書き方が主流
    - `setChanged()`
      - 状態が変化したというフラグを立てる
    - `notifyObservers()`
      - 状態が変化したというフラグが立っていたら，全observerのupdateメソッドを呼び出す
  - `Observer`インターフェース
    - 監視する側が実装する
    - `update(Observable o, Object arg)`
      - Observableの状態が変化すると呼び出される
