# 本文のハッシュをURLに載せて署名する方式

- Webhook の署名は、URL と本文の両方を対象にする必要がある
  - 本文だけに署名すると、本物の本文と署名を別の URL（別の受け口や別のクエリ）へ送り直されても見抜けない
- Twilio は JSON の本文を送るとき、本文の SHA-256 を `bodySHA256` クエリとして URL に入れ、その URL に HMAC で署名する
  - HMAC(鍵, URL + SHA-256(本文)) は、HMAC(鍵, URL + 本文) と同じ効き目を持つ。違う本文から同じハッシュを作ることが事実上できないため
- 受け手は、次の2つをどちらも照合して初めて本文を守れる
  - 署名の照合：その URL を送り主が作ったことを確かめる
  - ハッシュの照合：本文の SHA-256 が `bodySHA256` と一致することを確かめる
- 片方だけでは穴が残る
  - 署名だけ：本文は署名の対象に入らないので、本物の URL と署名を使い回せば本文を差し替えられる。`bodySHA256` を知らない古い SDK でも署名の照合は通るため、この状態に気づきにくい
  - ハッシュだけ：SHA-256 は鍵なしで誰でも計算できるので、偽の本文のハッシュを URL に入れれば一致させられる
- どちらの方式でも、署名の対象にタイムスタンプがなければ、本物のリクエストを丸ごと送り直す攻撃（リプレイ）は防げない
- 出典：[Webhooks Security](https://www.twilio.com/docs/usage/webhooks/webhooks-security)
