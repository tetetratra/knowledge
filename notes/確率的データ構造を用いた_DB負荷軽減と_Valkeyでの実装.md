# 確率的データ構造を用いた DB 負荷軽減と Valkey での実装

- Bloom Filter
  - > ABEMA の広告配信サーバーには、このような性質のリクエストがピーク時には数千から数万 RPS で発生します。
  - 読み取りのアクセスパターンとして「リクエストのカーディナリティがデータのカーディナリティを大きく上回る」状態
    - データのバラツキよりもリクエストのバラツキの方が大きい
      - リクエストに対して実際にデータが存在しない
  - Bloom Filter というデータ構造を活用
    - Bloom Filter：「あるデータが特定の集合に含まれるか」を、(偽陽性的に)確率的に判定
      - 偽陰性ではないので安心して使える
    - そのままだと増え続けて偽陽性が増えるので、一定期間ごとに Bloom Filter を交換 (ウィンドウ的にずらしていく)
