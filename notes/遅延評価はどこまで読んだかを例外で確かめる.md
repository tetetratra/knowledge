# 遅延評価はどこまで読んだかを例外で確かめる

- 遅延評価のコードが必要な分だけ読むことは、読まれたら例外を投げる列を渡すとテストできる
  - `Enumerator.new { raise ... }`は、最初の要素を求められた時点でブロックが動き、例外になる
  - 読まれた回数を数えるモックを用意しなくても、「どこまでは読まず、どこから読むか」の境界を直接書ける
- 例：見出しと本文の行をつないで返すストリームが、見出しを返すときに本文を読まないこと

```ruby
it '見出しは rows を読まずに返し、rows は2つ目の要素で初めて読む' do
  rows = Enumerator.new { raise 'rows が読まれた' }.lazy
  stream = build_stream(header: "id,name\n", rows: rows)

  expect(stream.first).to eq "id,name\n"
  expect { stream.first(2) }.to raise_error(RuntimeError, 'rows が読まれた')
end
```

- `first`が通り、`first(2)`で例外になることから、1つ目までは`rows`に触れず、2つ目で初めて読むと分かる
- 実装が途中で`to_a`などを呼んで全部読むように変わると、`first`の時点で例外になり、テストが落ちる
