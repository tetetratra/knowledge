# Linux: メモリ管理

| 記憶領域管理 |  |
| レジスタ、キャッシュメモリ、メモリ、ス トレージ、の昇順に低速・大容量 |  |
| プログラムのデータやコードは、基本的にメモリに置かれる |  |
| 要求時ページング |  |
| 実行時に実際にプロセスの全デー タ分の領域を確保するのではなく、仮想的に確保したことにしておき、実際に使われる時になって から実際の物理メモリを確保する |  |
| 無駄なメモリ消費を抑えられる |  |
| `sar -r` コマンドを用いると、プロセスが実際にどれほどの物理メモリが使われているのかを確認できる |  |
| 時間ごとの物理メモリ割り当ての増減は `sar -B` |  |
| 物理メモリのアドレスをそのままプロセスが利用すると、複数プロセス実行時のアドレス被りの防止が困難になるため、プロセスごとにページテーブルというものが作られ、0 から始まる仮想ア ドレスと物理メモリのアドレスを対応付けている |  |
| 仮想アドレスは木構造のような階層構造になっ ており、必要に応じて枝葉が作られるため、ページテーブルのために更に必要になるメモリは小さい容量で抑えられている |  |
| メモリアクセスを高速に行うため、一度メモリから取ってきたアドレス周りのデータを、メモリよりも高速にアクセスできるキャッシュメモリメモリという場所に保管する仕組みがある |  |
| 配列の順次アクセス等で活かされやすい |  |
| メモリ上のデータを読み込んだだけであれば、キャッシュメモリとメモリの同期の心配は不要だけど、データを書き込んだ際は同期の問題が出てくる |  |
| ライドバック方式という、キャッシュメモリの値を書き換え時に、そのアドレスにダーティーという印を付けておき、そのアドレス のキャッシュメモリが捨てられるときに元メモリに書き戻しの処理を行うことで対応している |  |
| メモリが足りなくなった場合、ストレージをメモリとして使うようになり、ストレージへのメモリの書き込み, 書き戻しをスワッピング、ストレージ上のメモリを仮想メモリと呼んでいる |  |
| `free` や `swapon --show`コマンドで、システムのスワップ 領域のサイズや場所を確認できる |  |
| 現在のスワッピングの発生の有無は `sar -W`で、その増減は`sar -S`で調べられる。 |  |
