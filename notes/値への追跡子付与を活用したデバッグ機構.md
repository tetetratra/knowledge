  - 値への追跡子付与
    - 関心のある情報のみを抽出するためのクエリ言語を提案
  - 値への追跡子の付与
    - 追跡子には、式を評価した時刻を含める
    - 3種類の追跡子
      - 通過したプログラム中の場所
      - 値の生成源
      - ユーザ指定の文字列
  - 値が通過したプログラム中の場所を記憶する追跡子
    - 時刻が保存されるので、順番も保存される
  - 値の生成源の値(生成のために使用された値)を記憶する追跡子
    - >値 v_in を使用した**演算の結果の値**として，値 v_out が新たに生成される場合，
      - 算術演算だったらその項
      - 配列アクセスだったら配列オブジェクトとインデックス
    - >または，値 v_in は条件文(if，for，while)の条件式の評価結果の値であり，その条件文の分岐の**ブロック内の式の評価結果として値 v_out が新たに生成**される場合，
  - ユーザ指定の文字列を記憶する追跡子
    - 特殊形式 MARK(exp, marker) を導入
    - マークの付け方3通り
    - 1. 式 exp の評価結果の値
    - 2. 1に加えて、部分式の評価結果の値
    - 3. 1に加えて、その式を評価している間に評価された他のすべての式の評価結果の値
  - グラフが作られる
  - クエリで絞る
    - 値を指定して追跡子で絞るもの
    - 追跡子指定して値で絞るもの
      - 追跡子が複数個指定された値について、論理演算的に絞るクエリもある
  - 設計と実装
    - プログラム変換
    - 追跡子保持能力付きの値を表すデータ構造を導入
      - >プログラム実行時のすべての値はこのデータ構造のインスタンス
      - コード内の全ての式をMARK関数でラップ
        - `exp -> MARK(exp, 付与する追跡子に与える情報)`
        - MARK関数は、jsの値を内包したデータを返す
          - この値に`+`演算子などを適用するとエラーになる問題
            - `+`演算子などに使われる値は`MARK_D`でラップして解決
      - MARK, MARK_D関数が受け取った引数がjs値なら、生成源の値を記憶する追跡子を付与
        - それは新しく生成された値なので
          - js内部の演算子とかが使われて作られた値
    - 追跡子に付与する情報
    - 1. プログラム中の場所
      - 行と列の情報を与えるだけ
    - 2. 評価結果の値の生成源となる可能性のある値
      - 例：`a[i]`について
        - `a[i]`の直接の生成源は動的にしかわからないが、
        - 間接的な生成元となることが確実な値は`a`と`i`であり、これは静的にわかる
        - (変換されたコードの)実行時、`a[i]`のマーク処理時には、`a`と`i`を参考に生成源の追跡子を付ければ良い
    - 3. ユーザ指定の文字列
      - マークの付け方によって実装が異なる
        - >  1. 式 exp の評価結果の値
          - そのままその値にのみつければよい
            - `a[i]`なら`a[i]`のみにつける
        - >   2. 1に加えて、部分式の評価結果の値
          - これもちょっと解析すれば静的にわかる
            - `a[i]`なら`a[i]`と`a`と`i`につける
        - >   3. 1に加えて、その式を評価している間に評価された他のすべての式の評価結果の値
          - `a[i]`なら`a[i]`と`a`と`i`に加えて、`a`の評価結果と`i`の評価結果に付与する
            - 「`a`の評価結果と`i`の評価結果」は静的には決定不可能
          - `a[i]`の評価直前に、ユーザー定義のラベルをグローバル的に保持しておいて、内側の値の評価時にはそれを参照すればよい
            - `exp -> (save(), push(marker), tmp = mark(exp,...), restore(), tmp)`
            - 例外への対応のための処理もするけど略
    - MARK関数まとめ
      - 入力
        - >追跡子付与対象の値(元の言語の値，または，追跡子保持能力付きの値)
        - >付与対象の追跡子(場所，生成源になりうる値，ユーザ指定の追跡子文字列)
        - >追跡子付与対象の値を大域的な表に記録するための ID
      - 出力
        - >追跡子保持能力付きの値
      - 処理
        - >1. 追跡子付与対象の値が元の言語の値の場合，その値から新たに追跡子保持能力 付きの値 v_new を作成し，v_new に生成源になりうる値を記憶する追跡子を付与 する.最後に，すべての追跡子付きの値を格納しておく大域コンテナ values に v_new を格納する.また，以降の手順では，v_new を追跡子付与対象の値と する.
        - >2. 追跡子付与対象の値に対して，通過場所を記憶する追跡子，ユーザ指定の追跡 子文字列，dynamicMarkers 内に格納されている追跡子をそれぞれ付与する.
        - >3. 追跡子付与対象の値を ref に入力の ID で記録する.
    - 変換の実装
      - mark → `_PASS`, mark' → `_GETVAL`
      - アトム・シンボル
        - 外の文脈に応じて`_PASS, _GETVAL`
```js
_PASS(1, loc, [])
_PASS(’hoge’, loc, [])
_PASS(true, loc, [])
_PASS(null, loc, [])
_PASS(undefined, loc, [])
_PASS(NaN, loc, [])
```

- 配列・オブジェクト
  - 外の文脈に応じて`_PASS, _GETVAL`
  - 生成元情報に、要素やプロパティを入れる
```js
_PASS([exp1, ..., expn], loc, [_REF[’id(exp1)’], ..., _REF[’id(expn)’]])
_PASS({prop1 : exp1, ..., propn : expn}, loc, [_REF[’id(exp1)’], ..., _REF[’id(expn)’]])
```

- 変数式
  - `_PASS, _GETVAL`
- 二項算術
  - 全体は`_PASS, _GETVAL`
  - 個々は`_GETVAL`
- 配列参照式`exp1[exp2]`
  - まずは`exp1`と`exp2`を変換しておく
  - 全体は`_PASS, _GETVAL`
  - `_PASS(exp1[exp2], loc, [_REF[’id(exp1)’], _REF[’id(exp2)’]])`
    - 配列・オブジェクトを作るときと似た雰囲気
- メンバ参照式
  - メンバ名 prop は静的な識別子のため，変換しない
  - `_PASS(exp.prop, loc, [_REF[’id(exp)’]])`
- 関数呼出式`exp1(exp2, ..., expn)`
  - まずオペレータとオペランドの式を再帰的に変換
  - オペレータが組み込み関数なのか、ユーザー定義の関数なのかは静的にはわからない
    - オペランドの式は決め打ちで`_PASS`
    - >対象の式を`_GETVAL`関数で変換することを指示するための特殊形式を関数`DETACH_MKR(exp)`として用意
      - >ユーザの判断で適切な変換を指示できるようにした
        - 関数が組み込みかどうかはユーザーに頑張って判断してもらう
  - `_PASS(exp1(exp2,...,expn), loc, [_REF[’id(exp1)’], ..., _REF[’id(expn)’]])`
  - `exp1.prop(exp2, ..., expn)`の形だと、メンバ参照式の規則とかち合う
    - 対処方法は省略
