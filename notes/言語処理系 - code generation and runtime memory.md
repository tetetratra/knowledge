# 言語処理系: コード生成と実行時メモリ

- **アセンブリ言語へコード生成**
- x86のアーキテクチャを対象にコード生成
  - スタックに値や番地を入れていって計算
    - 番地は大きい方から小さい方で伸びていく
  - スタックポインタespレジスタ
    - 関数呼び出し直後は ebp=esp になる
    - 関数呼び出しの中で上下に動く
  - ベースポインタebpレジスタ
    - ebpの指すアドレスには旧ebpが指していたアドレスが入る
    - 関数呼び出しの最中は同じ場所を指している
  - eaxレジスタ
    - 関数の返り値を入れるレジスタ
**stack**

| esp |  |  |  |
| --- | --- | --- | --- |
|  | ~ |  | <= 局所変数とか一時的な値の格納 |
|  | ebp-8 |  | <= (同上) |
| ebp-4 |  | <= (同上) |  |
| ebp | 旧ebpの値 |  |  |
| ebp+4 | 帰り番地 | <= 関数の実行終了後に制御を戻す場所 |  |
| ebp+8 | 第1引数 |  |  |
| ebp+12 | 第2引数 |  |  |

- ↑このひとまとまりをスタックフレームという
  - ローカル(局所変数)
    - スタック上orレジスタに置かれる
  - 静的変数(staticなもの)
    - スタックではないメモリ上に置かれる
- **使い方**
  - lexファイルの使い方
    - 字句解析、終端記号の解析
    - `lex`コマンドでlexファイルをコンパイルすると、`.yy.c`ファイルができる(Ｃ言語のファイル)
      - `yylex()`関数が作られる。返り値はlexファイルの右側で指定した定数とか
    - このC言語ファイルをメインのCプログラムでincludeする
    - そしてメインのCプログラムを、`cc foo.c -ll`とコンパイル
      - `-ll`はlexのライブラリを指定している
  - yaccファイルの使い方
    - 非終端記号の解析
    - `yacc`コマンドでyaccファイルをコンパイルすると、`.tab.c`ファイルができる(C言語)
      - これは、`yylex()`関数を呼ぶことでlexで解析した終端記号を読み込んでいる
    - このC言語ファイルをメインのCプログラムでincludeする
      - `yyparse()`で解析を始める
    - `cc piyo.c -ll -ly`でコンパイル
      - `-ly`でyaccライブラリを指定
  - yaccの機能
    - `$n`で(nは1から)、マッチしたn番目の属性値が入る
    - `$$`に左辺の非終端記号の属性値を入れる
      - `$n`数値とかなら実際に足したりしたものを`$$`に入れる
  - 変数
    - 記号表という、変数名と値の構造体の配列を使って実現
  - 構文木
    - 種類、値(or 左)、右(or NULL) の構造体の配列で実現
    - ノードを作る関数は、自身の配列内での添字をindexとすることで、親に自身を渡している
- **C言語のメモリの割り当て**
- そもそもメモリの場所の種類がある。上から、
  - スタック領域
    - ローカル(局所)変数。
  - 空き領域
  - ヒープ領域
    - コード内で確保されるメモリ(mallocとかで)はここ。動的変数の示すメモリはここにある。
  - データ領域
    - グローバル(広域)変数はここに確保される。プログラムが終わるまで残る。
  - コード領域
    - 関数のアドレスが指しているのはこの場所
