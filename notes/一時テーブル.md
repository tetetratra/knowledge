# 一時テーブル

- EXPLAINで `Using temporary` が出ているとき、一時テーブルというものが作られてそこで処理が行われている
  - テンポラリーテーブル と呼ばれることも
- [第129回　Internal Temporary Table（内部テンポラリテーブル）について［その1］ | gihyo.jp](https://gihyo.jp/dev/serial/01/mysql-road-construction-news/0129)
  - テンポラリテーブルが作られる条件
    - > UNIONを使用したクエリ
    - > ORDER BY句と別のカラムのGROUP BY句を含むクエリ
    - > 複数テーブルのUPDATEステートメント
    - > GROUP_CONCAT() または COUNT(DISTINCT)評価
    - > ORDER BY句と組み合わせたDISTINCT句のクエリ
    - > 派生テーブル（FROM句内のサブクエリ）
    - > サブクエリまたはセミジョインのマテリアライゼーション用に作成されたテーブル
    - > 同一テーブル間でのINSERT..SELECTステートメント
    - > ウィンドウ関数を使用したクエリ
    - > 共通テーブル式（CTE）を使用したクエリ
  - 内部テンポラリテーブルに使用されるストレージエンジン
    - MySQL 5.6とそれ以前
      - インメモリテンポラリテーブル：MEMORYストレージエンジン
      - ディスクテンポラリテーブル：MyISAMストレージエンジン
    - MySQL 5.7
      - インメモリテンポラリテーブル：MEMORYストレージエンジン
      - ディスクテンポラリテーブル：MyISAM または InnoDBストレージエンジン
    - MySQL 8.0
      - インメモリテンポラリテーブル：TempTable
      - ディスクテンポラリテーブル：TempTable
      - TempTableエンジンという方式が出てきて、設定で変えられるようになった(デフォルトはどっちもTempTable)
      - 詳細：[第132回　Internal Temporary Table（内部テンポラリテーブル）について［その2］ | gihyo.jp](https://gihyo.jp/dev/serial/01/mysql-road-construction-news/0132)
- TempTable方式の実装等の詳細： [漢(オトコ)のコンピュータ道: そろそろTempTableストレージエンジンについて一言言っておくか](https://nippondanji.blogspot.com/2018/06/temptable.html)
- [日々の覚書: MySQL 5.7.6以降では暗黙のテンポラリーテーブルがあふれると死ぬ](https://yoku0825.blogspot.com/2015/04/mysql-576.html)
  - MySQLのバージョンによって、一時テーブルの処理エンジンが異なる
    - 〜5.7.5
      - テンポラリーテーブルのストレージエンジンにMyISAMを使う
      - テンポラリーテーブルがDiskを食いきってクエリーがアボートされるとストレージ容量は元に戻る
    - 5.7.6〜
      - テンポラリーテーブルのストレージエンジンにInnoDBを使う
      - 再起動まで容量が空かず、クエリーがアボートしても容量は開放されない
      - 再起動すると元に戻る
    - 8.0.13〜
      - 5.7.6で「クエリーがアボートしても容量は開放されない」だったのが治ったらしい
      - > この記事はMySQL 5.7を対象としたもので、MySQL 8.0.13とそれ以降ではこれは発生しないっぽくなっている（瞬間的に容量を食うのは一緒だが、mysqldを再起動しなくても容量が解放できるようになっている）
- MyISAMのディスクテンポラリテーブルはtmpディレクトリ配下に作られるらしい
- Aurora MySQL 2.10.0 には一時テーブルまわりの不具合があり、2.10.2 に上げれば治る
  - [Amazon Aurora MySQLの不具合でローカルディスクが枯渇しクエリが実行出来なくなった話 - Kaizen Platform 開発者ブログ](https://developer.kaizenplatform.com/entry/glidenote/2022-07-22)
  - 2.10.2は2022年リリース
- どうしてもインメモリではなくディスクテンポラリテーブルが作られてしまう場合がある
  - [tmp_table_size のチューニングとメモリ上に一時テーブルが作れないクエリ  - Qiita](https://qiita.com/tyoro/items/5436a5172b547e5e52f5)
    - メモリにつくる一時テーブルじゃ容量が足りないときはディスクに作られる
      - ディスクに作るときの基準値は、設定値`tmp_table_size`で変更できる
    - > tmp_table_size をいくら上げても、**ディスク上にテーブルが作られるのを抑制できない場合**があります。
      - これらの場合
        - テーブル内の BLOB または TEXT カラムの存在
        - GROUP BY または DISTINCT 句内の、バイナリ文字列の場合に 512 バイトまたは非バイナリ文字列の場合に 512 文字より大きい文字列カラムの存在
- AWS Auroraのストレージが無制限というのは、「永続データ用のストレージ (クラスターボリューム)」が無制限なのであって、一時テーブル用のストレージである「Aurora インスタンスのローカルストレージ」は固定値
  - [Amazon Aurora のローカルストレージについて調べてみた - Link and Motivation Developers' Blog](https://link-and-motivation.hatenablog.com/entry/2022/09/12/120545)
  - > エラーログ、一般ログ、スロークエリログ、監査ログ、および InnoDB 以外の一時テーブルの保存に使用
  - インスタンスタイプごとに固定で決まっている
    - [Managing performance and scaling for Amazon Aurora MySQL - Amazon Aurora](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/AuroraMySQL.Managing.Performance.html#AuroraMySQL.Managing.TempStorage)
    - たとえば `db.r5.2xlarge` は160GB、`db.r5.4xlarge`は320GB
- [Aurora MySQLでINDEX追加しようとしたら、ローカルストレージが枯渇して失敗した話 - CyberAgent SRG ](https://ca-srg.dev/752094914b564179a86d527b6138bd21)
- AWS Auroraでローカルストレージを調べたいときは、RDSのメトリクスから「FreeLocalStrage」で検索したグラフを見ればよい
- MyISAMのローカルストレージは壊れることがある
  - [MySQL :: MySQL 8.0 リファレンスマニュアル :: 16.2.4.1 MyISAM テーブルの破損](https://dev.mysql.com/doc/refman/8.0/ja/corrupted-myisam-tables.html)
    - `Incorrect key file for table: '...'. Try to repair it` というようなエラーメッセージが出てきたら可能性大
    - 本当に壊れているかどうかはコマンドを叩いて調査できる
