# トランザクションのネスト（入れ子）問題

- トランザクション
- データベース
- 分散トランザクション
- **「手続きAの中に手続きBが含まれるが、Aが失敗したらBも巻き戻ってほしい（しかしB単体でも動きたい）」**
- という要件のこと。
- （A,Bはそれぞれ複数DBを扱っている）
  - 前提として、ある処理におけるトランザクション管理はその処理が責任を負うべき
  - なので、上記例で言うと、Aの中でBで使っているトランザクションを改めて張るべき
    - Bが内部で張っているトランザクションは外部から呼べるように切り出しておくとヨシ
  - コードで書くとこんな感じ
```rb
class A
  def call
    b = B.new
    TableA.transaction
      B.transaction # 扱うテーブルのトランザクション開始・終了を連続させて、(アプリケーションロジックにおいては)原子性を担保する
        # なにかロジック
        b.call
        # なにかロジック
      end
    end
  end
end

class B
  def call
    transaction do
      # なにかロジック
    end
  end

  # 外から呼べるようにもしておくためにクラスメソッド化
  # 結果的に重複して張られても、そこはフレームワーク(rails)がよしなにスキップしてくれる
  def self.transaction(&block)
    TableB1.transaction do
      TableB2.transaction do
        black.call
      end
    end
  end
end

```
