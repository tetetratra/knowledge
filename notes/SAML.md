# SAML

- SAML とは何か？
  - 会社のアカウントで、社外のいろいろなサービスにログインできるようにする仕組み（SAML 2.0、2005 年）
  - 何が嬉しいのか？
    - 利用者は、サービスごとのパスワードを覚えなくて済む
    - 会社は、退職者のアカウントを 1 か所で止めるだけで、全サービスへのログインを止められる
- どうやって、別のサービスにログインさせるのか？
  - サービスは自分でパスワードを聞かず、利用者を会社のログイン画面へ案内する
  - 会社のログイン画面は、本人を確かめたら「この人は○○です」という証明（アサーション）をブラウザ経由でサービスに渡す
  - それぞれ何と呼ぶのか？
    - 会社のログイン画面の側を IdP（例：Entra ID、Okta）、サービスの側を SP と呼ぶ
- 証明はブラウザが運ぶのに、偽物でないとなぜ分かるのか？
  - IdP が証明に電子署名を付け、SP は IdP の公開鍵でそれを確かめるから
  - 公開鍵は、連携を始めるときに IdP が公開する設定ファイル（メタデータ）から登録しておく
  - そのため SP は、IdP が何であっても、登録した値を差し替えるだけで同じ作りのまま使える
- OAuth や OIDC とは何が違うのか？
  - OAuth は権限を貸す仕組みで、「誰か」を証明する ID トークンを足したものが OIDC
  - OIDC は SAML と役割が同じで、作りが違う
    - SAML はブラウザが XML の証明を届け、OIDC はサーバーが IdP と通信して JWT の ID トークンを受け取る
  - では、なぜ今も SAML が使われるのか？
    - 企業の IdP はほぼ必ず SAML に対応しているから
- もっと詳しくは？
  - 流れと運び方は「SAMLのSPとIdP」、受け口への攻撃は「巨大に膨らむ圧縮データは展開後のサイズ確認では防げない」
