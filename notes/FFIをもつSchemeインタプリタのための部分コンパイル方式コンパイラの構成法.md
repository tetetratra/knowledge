# FFIをもつSchemeインタプリタのための部分コンパイル方式コンパイラの構成法

- Scheme->C
  - Scheme-to-C コンパイラ
  - レキシカルスコープに対応するために
    - ディスプレイを使用して Scheme の変数のスコープを模倣
    - ディスプレイとは、グローバルな環境のようなもの
    - 関数のreturn時にディスプレイに入れた値を破棄する
  - 無限の寿命をもつ変数
    - 束縛をヒープに置く
    - 継続のために、束縛は値ではなく参照をもつ(Box化)
      - 参照なら、書き換わったときにそれが伝搬されるから
- Hobbit
  - Scheme インタプリタ SCM 用の Scheme-to-C コンパイラ
  - >コンパイル時 にすべての Scheme ソースプログラムが得られると仮定して大域的な解析を行うことで， クロージャの生成を抑制し素直な C プログラムへ変換できるような最適化を行っている
  - レキシカルスコープに対応するために
    - 入れ子の関数定義を C にコンパイルするために lambda-lifting を行っている
    - 自由変数を関数の追加の引数で受けとり、外側のレキシカルスコープを参照できるようにする
      - これにより、schemeレベルで、すべての関数の定義をトップレベルにできる
      - それをCに変換
  - 変数の寿命に対応するために
    - つまりクロージャを返すようなとき
    - クロージャをヒープ上のベクタに作る
      - そこに自由変数の束縛を保持する
- 部分コンパイル方式コンパイラ
  - >高度な技術を使用せずに比較的高性能なコンパイラを作成できるようにする
