- **15 暗号化モード**
  - AESのブロックを暗号化する方式はいくつかある
  - 「ECB (Electronic CodeBook) モード」
    - 決定的アルゴリズムである。確率的アルゴリズムでない。
    - 同じブロックならば暗号化したブロックも同じになってしまって、あまり安全ではない
    - パターンが解読されてしまう
  - 「CBC (Cipher Block Chaining) モード」
    - 一つ前の暗号化ブロックのXORを取ってから暗号化する
  - 「CTR (CounTeR) モード」

    - 各ブロックの並列処理ができる

- **18 鍵共有**
  - 「ディフィー・ヘルマン鍵共有(DH鍵共有)」
    - `g`と`n`は公開されている数字
    - お互いに秘密の数`a`を用意して、それを累乗につかった余り`g^a mod n`を教える
    - お互いに貰った値`b`を使って`g^ab mod n`を計算すれば、その値は2人だけのもの
  - DHP (DH Problem) の難しさを使った仕組み
    - 突き詰めると離散対数問題「`g, n, A`から`A = g^a mod n`を満たす`a`を求めよ」
    - `a`から`A`を求めるのは簡単だけれども、`A`となる`a`を求めるのは難しい→一方向性関数
- **19 有限体と拡大体**
  - 乗算表
    - modを取った値による掛け算表
  - 逆算表
    - 除算をうまく定義してあげる
    - `x (= 1/a)`を、`ax = 1`と考えて、「`a`に掛けたら`1`となる数」を`x`とする
  - 体
    - 加減乗除の四則演算ができる集合
    - modが素数ならいつでも除算が定義できる
  - 「有限体」
    - 有限個の集合 からなる体
    - $ \mathbb{F}_p = \{0,1,...,p-1\} (pは素数)
    - $ \mathbb{F}_2はビット演算と同じ
  - 「拡大体」
    - $ \mathbb{F}_2をまとめて扱う
    - 2つまとめて扱うと、$ \mathbb{F}_{2^2}
      - $ b_1 x + b_0のような感じ
      - $ 00 = 0x + 0 = 0
      - $ 01 = 0x + 1 = 1
      - $ 10 = 1x + 0 = x
      - $ 11 = 1x + 1 = x + 1
      - この$ xの式を使って加減乗除ができる

- **25 ハッシュ関数**
  - 「一方向性」
    - ＝ 「原像計算困難性」
    - h(a)からaを計算できないこと
  - 「衝突困難性」
    - 異なる2つのデータ（データはなんでもよい）で、そのハッシュ値が同じものを見つけるのが難しいという性質
  - 「第二原像計算困難性」
    - h(a)からh(b)=h(a)となるbを計算できないこと
      - h(a)という特定のデータ
  - ハッシュ関数いろいろ
    - 「MD5」
      - 現在は終了
    - 「SHA-1」
      - 現在は終了
    - 「SHA-256」
    - 「SHA-3」
  - たとえば携帯電話番号にハッシュ値を使ってはいけない
    - 070以降が8桁だから、ハッシュ値の全列挙で元の電話番号がわかってしまう
  - ストレッチング
    - ハッシュ計算を繰り返し行う
    - 繰り返した数分倍だけ耐性が増す
- **26 SHA-2とSHA-3**
  - SHA-2
    - ハッシュ値のサイズは選べる。256ビットだとSHA-256
    - 動作
      - データをブロックに分割する
      - 内部状態Sを用意（初期値Ⅳ）
      - 圧縮関数`f: (B, S) -> S'`を用意
      - ブロックごとに順々に、Sを更新しながら圧縮関数にかける
      - 最終的なSがハッシュ値
    - マークル・ダンガード構成
  - SHA-3
    - ハッシュ値のサイズは選べる
    - スポンジ構成
    - 動作
      - 内部状態S（初期値はゼロ埋め）
      - Sを撹拌する、置換関数f
      - 入力データをブロックに分割
      - `f(B[i] xor S[i]) = S[i+1]` のように繰り返す
  - SHA-256もSHA-3-256もハッシュのサイズは同じだけど、SHA-3の方が解析しにくい
- **27 SHA-1の衝突**
  - SHA-1は（SHA-2と同じ）マークル・ダンガード構成だから、最初の方で`S'`が同じになるような`B[n]`さえつくれれば、以降は元のデータをそのまま使えば良い

- 「FIDO」

      - FIDOアライアンスが認定したことの証明
        - >アテステーションの正当性はベンダーを含む信頼できる機関(FIDO サーバ)の検証鍵で検証できます
  - 登場人物
    - クライアントのアプリ・認証器・WebAuthnを利用するサーバーRP
      - Relying Party
    - FIDOサーバー
  - しくみ
    - 登録時

      - 検証鍵をPRサーバーに登録する（詳しくは略）

- **31 タイムスタンプ**
  - 署名の失効
    - いちどした署名を取り消すこと
  - 署名鍵の漏洩を嘯けば、言ったことを後で否認できる
    - 「100万円借りると言ったが、あれは嘘だ。なぜなら100万円借りるの発言のは他の誰かが漏洩した署名鍵を使って私の発言だと偽造したものだからだ」ができてしまう
    - 署名にタイムスタンプをつけて解決
  - タイムスタンプ
    - 「時刻認証局TSA（time stamping authority）」が必要
    - 認証局は時刻ごとのハッシュ値hをもっている
      - 後述の計算によって、計算ごとに更新される
    - 認証局は、時刻tで「データのハッシュ値d」を受けとると、`h' = H(h, d, t)`を返す
    - その後認証局は、`(h, d, t)`を世界に公開
      - 「ハッシュ値がdなデータについて、時刻tにおいては正しかったですよ」ということ
    - リンクトークン方式という
- **32 ブロックチェーンとビットコイン**
  - 「ブロックチェーン」
    - タイムスタンプの仕組みに似ている
    - 各データをハッシュ値でつなげて、それをP2Pで管理する仕組み
  - 「ビットコイン」
    - 「暗号資産（昔は仮想通貨、暗号通貨とも）」
    - 資産の移動履歴をブロックチェーンで管理
    - 移動履歴には送信元の署名をつける
    - 「ビットコインを持っている」とは
      - 本人の署名付きのビットコインの移動履歴がブロックチェーンに存在している
      - 署名鍵の喪失はビットコインの喪失
  - チェーンを正しく一本に伸ばすための人間心理やコンピューターリソースに基づいたしくみとかがあるけれども難しいからパス

    - GoogleやCloudflareが提供しているDNSサーバー
  - 「DoT (DNS over TLS)」「DoH (DNS over HTTPS)」
    - クライアント↔キャッシュDNSサーバー間の機密性と完全性を保証
  - 「SNI (Server Name Indication)」
    - 一台のサーバーで複数のドメインを管理するとき、TLSのClienthelloの中にアクセスしたいドメインを指定するTLSの拡張
      - VPS, レンタルサーバーとかが使う
    - SNIに暗号化したを加えた規格もある
- **41 メール**
  - 「SMTP (Simple Mail Transfer Protocol)」
    - メールの転送方法
  - 「[POP3](Post Office Protocol version 3)」
    - メールサーバからメールを取り出す方法
    - 取り出したらそのメールはメールサーバーから削除
      - pop?
  - 「IMAP4 (Internet Message Access Protocol version 4)」
    - メールサーバーから取り出すだけ。POP3とは違って取り出し後も消さない
  - 「多目的インターネットメール拡張 MIME (Multipurpose Internet Mail Extension)」
    - メールの拡張
  - 「S/MIME (Secure MIME)」
    - MIMEに秘匿性と完全性を追加
    - 送信者のクライアントから受信者のクライアントまで暗号化
      - E2E (End-to-End)な暗号化
    - 受信側が送信側の公開鍵を入手しておく必要がある
    - あまり普及していない
  - 「Webメール」
    - Gmailとか
    - webサービスとしてのメール
- **42 VPN**
  - インターネット標準であるRFC1122の、リンク層で指定されている規格
    - 有線ではイーサネット(Ethernet)
    - 無線ではIEEE 802.11
  - LANについて
    - LAN内の通信はイーサネットフレームでやりとり
    - LAN内の機器と外部との通信はルーターを経由
      - インターネットサービスプロバイダのインターネット回線を通る
  - 「VPN」
    - ネットワーク↔ネットワーク間を拠点間VPN
    - PC↔ネットワーク間をリモートアクセスVPN
    - 「トンネリング」
      - VPNゲートウェイ間で、送受信データがそのまま送受信されたかのように見せる仕組み
      - 「カプセル化」
        - トンネリングをするにあたってデータの暗号化などをする
    - レイヤ2 VPN
      - イーサネットフレームをトンネリング
      - OSI参照モデルでいうレイヤ2のことだと思う
    - レイヤ3 VPN
      - IPパケットをトンネリング
    - SSL-VPN
      - TLSを通してトンネリング
      - イーサネットフレームをトンネリングすればレイヤ2 VPNとして使える
    - IPsec
      - レイヤ3 VPNで使う
      - IPパケットに秘匿性と完全性を加える
- **43 HTTP/3**
  - 「SPDY (スピーディー)」
    - Googleが2012年にSPDYを制定
      - 高速なHTTP
  - 「HTTP/2」
    - IETFが2015年にSPDYを「HTTP/2」として標準化
    - 新機能
      - ストリームの多重化
      - バイナリベース
    - なお残る問題点
      - HOLブロッキング (Head-Of-Line blocking)
        - TCPレイヤーで不具合があると、そのパケットの再送までストリーム全体が止まる
      - TLSとTCPの2重管理問題
        - (TLSの復習) [Transport Layer Security - Wikipedia](https://ja.wikipedia.org/wiki/Transport_Layer_Security)
          - インターネット・プロトコル・スイート
            - = TPC/IP参照モデル
            - OSI参照モデル(7層)とは別なので注意
            - アプリケーション層(HTTP, HTTPS, POP, SMTP, SSH, NTP, ...)↔トランスポート層(TCP, UDP)↔インターネット層(IP)↔リンク層
          - トランスポート層↔アプリケーション層間の通信について規定
          - 認証、暗号化、完全性付与の機能
            - セキュリティのため
          - ClientHello, ServerHello, ClientKeyExchangeとかをするやつ
          - トランスポート層には必ずしもTCPを使わなくてもいい
          - アプリケーション層には何を使ってもOK
            - HTTPを使った場合、HTTP + TLS = HTTPS となる
        - (TCPの復習)
          - エラー訂正機能
            - 通信自体の故障に対応するため
          - SYN, SYN/ACK, ACK とかの3-wayハンドシェイクとかはこっち
        - TCPでTLSをすると、データ順序の保証機能、通信終了の確認機能、輻輳制御機能などが被るため非効率
  - 「QUIC」
    - Googleが提案
    - UDPを利用
    - 「Connection ID」を用いてHOLブロッキングを解消
    - エラー訂正の処理はQUICが担うので無駄がない
    - QUICの処理はアプリケーションで行う
      - TCPでは処理はOSの役目だった
    - 「コネクションマイグレーション」機能
      - IPアドレスやポート番号に依存しないので、切替時に通信が途絶えない
  - 「HTTP/3」
    - HTTP/QUICがHTTP/3となった
    - 2018に制定
    - TLSはハンドシェイクに専念

- **45 準同型暗号**
  - 準同型暗号
    - （数値と同じように）暗号文の足し引きができるから、同型
      - 本当はちょっと違うから準同型
  - 平文用の関数$ fから、暗号文用の関数$ \tilde{f}をつくる
    - $ Enc(f(m)) = \tilde{f}(Enc(m))
  - データを暗号化したままデータの計算ができるので、ビックデータの解析などに便利
- **46 秘密計算**
  - 秘密計算
    - データを秘匿したまま計算する技術の総称
  - マルチパーティ計算 MPC (Multi-Party Computation)
    - 複数人で協調して計算すること
    - 互いに持ち寄った`s`で、`f = (s1, s2, ...)`を計算する
  - 全員がプロトコルに従っていれば秘密は守られる、という仮定と、誰かが悪意で虚偽のデータを与える可能性も考慮する、という仮定がある
  - 秘密分散
    - あるデータを分散させて置いておくしくみ
    - 愚直に半々にしたりすると、片方がバレたらそのデータの半分がバレることになるのでダメ
    - 片方をワンタイムパッドの鍵にして、もう片方をその鍵で元の文を暗号化したものにすれば、どちらか片方がバレても大丈夫

  - 署名のしくみに近い
