# 負荷検証環境構築

- いろいろな会社の事例とか
  - [負荷改善の取り組みとして本番相当のデータを再現したloadtest環境を構築した話](https://zenn.dev/aldagram_tech/articles/54195274379228)
    - 他の検討案
      - seed機能
    - 仕組み
      - (AWS Step Functionsで) 本番相当のデータを自動的に同期する仕組みを構築
        - Auroraクラスターを作成
        - 個人情報のマスク処理
        - DB以外は特に検証環境を作っていなさそう?
    - 運用
      - EventBridgeを用いた定期的な自動実行
        - 週1の間隔で自動実行
  - [Kubernetes上に負荷試験基盤を構築した話 - Sansan Tech Blog](https://buildersbox.corp-sansan.com/entry/2024/07/25/140000)
    - 仕組み・運用
      - 1. GitHub Actionsから負荷試験を実行
      - 2. シナリオファイルを含むDockerイメージをECRにpush
      - 3. k6のCustom resourcesをクラスターに作成
      - 4. k6-operatorが3.を検知し、負荷をかけるJobを作成
      - 5. 任意のAPIに対して負荷をかける（リアルタイムでDatadogにメトリクスを送信）
      - 6. テスト完了後サマリをSlackに通知
    - 負荷のパラメーターも簡単に指定できるような仕組みで構築
  - [WEARアプリリニューアルにおける負荷試験事例（計画編） - ZOZO TECH BLOG](https://techblog.zozo.com/entry/2024-newwear-load-test-plan)
    - 仕組み
      - 試験環境に本番環境を利用(!)
        - 検証専用の環境を作るにあたって、本番相当のDBやデータを揃えるのが難しかったため
      - 単体APIごとと、シナリオを使った負荷試験の両方を試験
    - (本番環境上でやっているので) 負荷量を段階的に増やして試験している
  - [WEARアプリリニューアルにおける負荷試験事例（実施編） - ZOZO TECH BLOG](https://techblog.zozo.com/entry/2024-newwear-load-test-implemention)
    - 発生した課題
      - 負荷試験中にロックが発生
  - [Argo WorkflowsとGatlingで作るスケーラブルな負荷テスト環境 - asoview! Tech Blog](https://tech.asoview.co.jp/entry/2023/12/01/093711)
    - 仕組み
      - 負荷テストのときのみ、STG環境を本番相当のスペックに変更してテストしている
    - 運用
      - テストシナリオを作成してコミット
      - Argo Workflows (Kubernetes上で動くなにかツール) の画面上から都度実行
  - [ZOZOのプラットフォームSREによる負荷試験  - Qiita](https://qiita.com/gold-kou/items/e88070f147108512e2af#%E8%B2%A0%E8%8D%B7%E8%A9%A6%E9%A8%93%E7%92%B0%E5%A2%83)
    - 確認項目
      - レイテンシ
      - 垂直スケーリングすると線形にスループットが増えるかどうか
    - 仕組み
      - stg環境(prd環境とほぼ同じ構成)を利用
        - テスト中はオートスケーリングしないように設定
    - 運用
      - stg環境は1個しかないので、チーム間で調整して都度実行
  - [大規模サービスの負荷試験を改善していった話 - Speaker Deck](https://speakerdeck.com/5st7/da-gui-mo-sahisunofu-he-shi-yan-wogai-shan-siteitutahua?slide=13)
    - 記事版: https://zenn.dev/qubena/articles/2ad3f468a7c70f
    - しくみ
      - 別途負荷検証環境を構築
      - 本番DB同等のデータを匿名化して利用
    - 改善したこと
      - 実施手順を減らした
      - ダッシュボードを用意した
      - 手動に加えて自動でも負荷試験が行われるようにしていた
  - [【インターン参加記】GitHub Actions Self-Hosted Runnerによる負荷試験環境構築の自動化 | Recruit Tech Blog](https://techblog.recruit.co.jp/article-654/)
