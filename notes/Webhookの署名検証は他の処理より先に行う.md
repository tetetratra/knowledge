# Webhookの署名検証は他の処理より先に行う

- Webhook のエンドポイントには誰でもリクエストを送れ、送り主を確かめる手段は署名ヘッダー（Twilio の `X-Twilio-Signature` など）の検証だけ
- 署名の検証より前に本文の JSON の解析や DB の検索をすると、第三者がその処理を動かせる
  - 失敗をエラー監視サービス（Rollbar など）へ送る作りなら、でたらめな本文を送るだけでエラーを記録させ、本物の通知を埋もれさせられる
  - WAF のマネージドルールは既知の攻撃パターンを見るもので、壊れた JSON やでたらめな ID は止まりにくい
- 対策
  - 署名の検証を最初に行い、失敗したら本文を読まずに 4xx を返す
  - 検証に必要な鍵を引くために先に処理が要る場合も、検証前の失敗はエラー監視に送らず、ログやメトリクスで数える
