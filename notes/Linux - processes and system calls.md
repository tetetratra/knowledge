| システムコール |  |
| プロセスの操作やハードウェア (I/O) の処理、CPUの特殊な命令を呼び出すためにある |  |
| CPU にはユーザーモードとカーネルモードという 2 種類の状態があって、 OS の機能を直接触れるのはカーネルモードの時だけ |  |
| 普段書くコードはユーザーモードで 動いて、システムコールを経由してその OSの操作をしている |  |
| システムコールはカーネルモードで動いて、ユーザーはシステムコールの改竄はできないから、安全にOSの機能を使える |  |
| C 言語のprintf 関数とかは、内部でwrite システムコール等を呼ぶことで実装されている |  |
| この write 関数などが C 言語には用意されているけど、狭義にはこれ自体がシステムコールじゃなくて、アセンブリ言語のsyscall 命令をラップしているもの |  |
| プロセスが発行したシステムコールはstrace コマンドで確認することができる |  |
| [strace コマンドの使い方をまとめてみた - sonots:blog](http://blog.livedoor.jp/sonots/archives/18193659.html) |  |
| 「MySQLがどの設定ファイルをどの順で読み込んでいるか」とかを調べられるらしい |  |
| プロセスがどの CPU モードでどれほど動いていたかを確認するにはsarコマンド |  |
| C言語で、文字を出力する命令 (printf 等) が呼ばれたとき、ある程度バッファに溜めてか ら 1 度だけ write を呼ぶことで、システムコールにかかるボトルネックを軽減している |  |
| mallocとかでメモリを獲得する際も同じで、要求以上のメモリを予め確保しておいて、そこから割り当てることで、メモリ割り当てのmmapシステムコールのボトルネックを減らしている |  |
| プロセスの複製 |  |
| プロセスの複製をするシステムコールが用意されている |  |
| fork システムコールでは、自身のコ ピーのプロセスを作り、fork を呼び出した箇所からコピープロセスは動き出す |  |
| プロセス id を用 いて自身が親か子かを判別し、親は子の終了を待つ wait システムコール等を使い、プロセスの制 御ができる |  |
| exec システムコールでは、自身のプロセスを別のプロセスにまるごと置き換える |  |
| 例 えばシェル (bash とする) の echo コマンドが呼ばれた際、bash は自身のクローンを fork で作り、 その後即座に exec で echo のプロセスに化けることで実装している |  |
| 子プロセスは親プロセスとファイルを共有することで、ファイル複製の処理を省いている。どちらかに書き込みが起きたときに初めてファイルを複製し始める、copy on write という方式 |  |
| プロセスの状態・実行 |  |
| プロセスの状態には次のがある |  |
| 実行状態 |  |
| CPU は使ってる |  |
| 実行可 (実行待ち) 状態 |  |
| 実行可状態は CPU の空きを待っている |  |
| 待ち (スリープ) 状態 |  |
| IO 等の処理を待っている |  |
| ゾンビ状態 |  |
| 親が自身のプロセスの終了を受け取るの を待っている |  |
| psの3列目の STAT フィールドに状態は書かれている |  |
| 1つのCPUは1つのプロセスしか処理できないため、プロセスが複数ある場合は実行するプロセスを高速に切り替えて並列に処理している |  |
| 切替の仕組みには、コンテキストス イッチというやりとりが行われている |  |
| 実行中のプロセスのレジスタを退避させることでコンテキストを切り替えていて、C 言語では setjmp,longjmp 関数がこの処理を提供している |  |
| 複数プロセスの同時実行時、どのプロセスから先に行うかを決める方法はいくつかある。以下の通り(混ぜ合わせた方式も存在する) |  |
| 到着順 |  |
| プロセスの到着順に処理をする。すぐ終わるプロセスであっても待たされることが あるなど、バランスは良くない |  |
| 最短時間順 |  |
| プロセスにかかる時間が少ない順に処理をする。プロセスの終了時間が既知で ある必要がある |  |
| 優先度順 |  |
| ユーザーが独自に設定した優先度順に処理を行う. niceコマンドとか? |  |
| 最小残余時間優先 |  |
| 最小時間順がベースだが、新規プロセスが現在のプロセスよりも早く終わる場合はそちらを優先 |  |
