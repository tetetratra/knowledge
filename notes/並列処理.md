# 並列処理

- パラレル
- 物理的に同時な方(並行処理は論理的?に同時)
- 概要
  - 主記憶とPE(processing element)の結合で分類がある
    - 共有メモリ
      - 相互のPE間ではメモリを直に共有してやりとり
    - 分散メモリ
      - 相互の通信はメッセージパッシングとかの方式になる
    - 分散共有メモリ
  - 同期の種類
    - 条件同期
      - 他のPEの処理が終わるまで待つ
    - バリア同期
      - 全PEがバリアポイントに到達するまで待つ
      - `Promise.all()`みたいな感じかも?
    - 相互排除同期
      - 同時アクセス可能なPE数を制限
        - 1となることが多い
        - DBにレコードとしてジョブ入れて誰かが取る、みたいな感じかも?
        - DBのロックとかもこれかも
- 手法とか
  - 速度向上率 \(S = T_1 / T_n\)
    - \(T_1\) は1つのPEで、\(T_n\) はn個のPEで、処理したときの時間
  - 並列処理効率 \(e = S/n\)
    - 10個に増やして5倍になったらe=0.5
    - e=1をリニアスピードアップ、という(普通無理)
  - 並列化の手順
    - 並列性の抽出
    - タスクスケジューリング
    - コード生成
  - 先行制約
    - あるタスクを行うためには他のタスクの完了が必要、のような制約
    - 依存を図にしたものをタスクグラフ
  - タスクスケジューリングの種類
  - スタティックスケジューリングとダイナミックスケジューリングがある
    - サイクリック(静的)
      - ループを「Nの倍数、N+1の倍数、、、N-1の倍数」のように分割
    - ブロック(静的)
      - 「0~10, 10~20, 20~28」のように分割
    - セルフスケジューリング(動的)
      - グローバルなincrementする値(iglobal)を使う
      - DBでジョブをレコードとして作って、あいてるサーバーが取っていくのに似てる
    - チャンクスケジューリング(動的)
      - セルフスケジューリングの改良で、iglobalをある程度まとめて増やす
    - ガイデッドセルフスケジューリング
      - チャンクスケジューリングの改良で、徐々にigobalの増やす値を減らす
  - ループの並列実行方式にはいくつか手法がある
    - ループリストラクチャリング
      - ループ内処理の一部分でデータ依存があるときに、そこのみは排他的にする
      - 全部は無理でも、一部分を並列にできる
```c
for(i=1,i<n,i++){
  wait(sync, i-1);
  // 前のループに依存して、次のループが依存する処理
  a[i] = a[i-1] + 2;
  post(sync, i);
  // 前後のループに依存していない処理
  print("hello");
}
```

- ループ交換
  - 依存が起きないループを外側にして並列にすることで、同期回数をへらしてオーバーヘッドが減る
```c
forall(j=0; j<N, j++){ // 並列にできるfor. jはj-1とかに依存していない
  for(i=0, i<M; i++){
    // 並列にできないfor. iはi-1とかに依存している
  }
}
```

- ループ分割
  - 1つのforを2つのforにすることで並列にできる
```c
// 前のループに依存しているから並列にできない
for(i=0; i<n; i++){
  a[i] = b[i] + c[i];
  d[i] = a[i-1] * 4; // データ依存
}
// ↓↓↓
// 並列にできる
forall(i=0; i<n; i++){
  a[i] = b[i] + c[i];
}
forall(i=0; i<n; i++){
  d[i] = a[i-1] * 4;
}
```

- ストリップマイニング
  - 1つのforを2重のforにして、外側を並列にすることで、どの程度のブロックで並列化するかをコードに明示できる
    - 並列の手法というより読みやすいコーディングの手法な気がする...?
- サイクルシュリンキング
  - `a[i+16] = a[i]`のようなコードが1重for内あったとき、2重forにして、mod16で並列にできる
- ループ融合
  - 座標をxとy別々でforすると、片方のforしか並列化できないけど、よくある「余りと商」で1重にするやつをやれば1重のforになって、全部並列化できる
    - 2重forallは禁止されている、だから1重にした。ということなのかも?
- スカラ拡張
  - ループの外側の変数を使ってループ内で書き換えちゃうと並列化できないから、そういうときはローカル変数にする
- 並列処理をする環境
  - OSの機能
    - プロセス間通信
    - スレッド間通信
  - pthradライブラリによる並列化
    - `pthread_create`
      - 子スレッドを生成
    - `pthread_join`
      - 生成したスレッドの終了を待つ
    - スレッド間同期を図るAPIがいくつかある
    - コード例
```c
int *sum(int *arg_ptr) {
int lb = *arg_ptr;
int ub = *(arg_ptr+1);
int i, sum;
int *p;
  for (i=lb, sum =0; i<= ub; i++) { sum += i;}
  p = malloc(sizeof(int));
  *p = sum;
  return p;
}
/* --------------------------------- */
#include <pthread.h> // ヘッダファイルの読み込み
#include <stdio.h>
#include <stdlib.h>
int *sum(int *);
pthread_t th1, th2; // スレッドID変数

int main() {
  int *ps1, *ps2;
  int arg1[2]={1,5}, arg2[2] = {6,10};
  // 二つのスレッド生成
  // sum: スレッド開始関数, arg1: スレッド開始関数への引数 
  pthread_create(&th1,NULL,(void*(*)(void*))sum, &arg1);
  pthread_create(&th2,NULL,(void*(*)(void*))sum, &arg2); 

  // pthread_join: スレッドの終了待ち, ps1: スレッド終了状態
  pthread_join(th1, (void**)&ps1);
  pthread_join(th2, (void**)&ps2);

  printf("%d+..+%d=%d¥n", arg1[0], arg2[1], *ps1+*ps2);
  free(ps1);
  free(ps2);
}

```
