# ログ処理

- Rubyの場合のログ処理。多分他の言語でも同じはず..
  - [class Logger (Ruby 2.7.0 リファレンスマニュアル)](https://docs.ruby-lang.org/ja/latest/class/Logger.html)を使う
    - 使い方は、[標準添付ライブラリ紹介 【第 2 回】 Logger](https://magazine.rubyist.net/articles/0008/0008-BundledLibraries.html)が詳しい
  - 直接putsで出力する方法だと、stderrがバッファに溜まってから吐かれるからstdoutと順序が入れ替わることがあるのに注意
  - ログは2種類ある
  - >ファイルなどにログを記録するための Logger
  - >syslog にログを記録するための Syslog
    - Rubyでは
      - >Logger とは、ファイルなどにログを記録するためのクラスです。
      - >Syslog モジュールとは、 UNIX のシステムのログ記録用プログラム (syslog) にメッセージを送るためのモジュールです。
  - syslogとは
    - [syslogとは - IT用語辞典 e-Words](http://e-words.jp/w/syslog.html)
    - > syslogとは、IPネットワークを通じて他のコンピュータへ時系列の記録（ログ）を伝送する標準プロトコル（通信規約）の一つ。また、そのプロトコルを用いてネットワークを通じてログを収集・記録するソフトウェア。
    - クライアントサーバーのログを、ログサーバーに送るときのプロトコル?
    - macでは`/var/log/system.log`にsyslogがたまる
    - linuxでは`/var/log/messages`
  - バッチ処理型のプロセス実行について
  - ローカル開発では、直接動かす
  - 細かい情報も、ターミナルに出してほしい
    - 最終的なサーバーでは、cronで定期的に動かす
      - ログファイルに、必要な分だけ出して欲しい
  - ログの吐き出し先
    - stdoutやstderr
    - ファイルへの書き込みは外側で
    - ファイル
      - 日付とかでファイル切り替えるのがよくある
      - 何日分のみ取っておく(それ以前は削除する)、みたいな感じでディクス圧迫を避けるスタイルがある
  - ログの吐き出し先
    - ローカルでは(手動実行)
      - stdout => ターミナル
        - rescue内でのputsとか
      - stderr => ターミナル
        - rsecueできていないエラーとか(極力なくすべき)
      - sqlログとかも出す
        - `ActiveRecord::Base.logger = Logger.new(STDOUT)`
    - サーバーでは(cron実行)
      - stdout => ファイルに書き出す
      - stderr => ファイルに書き出す
        - そもそもstderrは吐かれないような設計が良い(stdoutとして出す)
      - activerecordのsqlログは吐かれないような設定にする
      - ファイル書き出しの処理をシェル側でやるかRuby側でやるかは時と場合次第
  - シェル側でファイルに出力
    - Ruby側ではエラーのrescue漏れは極力なくす
    - 外側のシェルで、stdoutとstderrをログファイルに書き出す
      - `hoge.rb 1>>file 2>&1` みたいな感じで書く
      - [標準出力と標準エラー出力をファイルに追記する - Qiita](https://qiita.com/CODA/items/aa0bc926c65ed3eb9f6e)
        - `1>>file`
          - >標準出力をfileに追記しますよー
        - `2>&1`
          - >標準エラー出力の出力先を標準出力の出力先と一緒にしますよー
    - Ruby側で、stderrとstdoutを同期させた方がいい
    - そもそもstderrは全く出さない設計がいい
  - もっと大掛かりに、色々な所からログを収集するときはツールを使うらしい。Fluentdとか(名前しか知らない)がそれらしい。
- **webアプリのログ**
  - nginxアクセスログ
    - `/var/log/nginx/access.log`
  - MySQLスロークエリログ
    - `SHOW GLOBAL VARIABLES like "%slow_query_log%";`で場所見つける
    - 重いクエリ分かったら`EXPLAIN`句で解析
  - Railsのログ
    - `log/staging.log`とかを見る
  - Logger
    - [class Logger (Ruby 3.0.0 リファレンスマニュアル)](https://docs.ruby-lang.org/ja/latest/class/Logger.html)
    - Loggerインスタンスを作り、debug, info, ... error, ... 等でログを吐かせる
      - Logger::Formatterを登録することでログの形式を指定
        - `Logger::Formatter#call(severity, time, progname, msg) -> String`
        - デフォルト設定だと`I, [2021-10-11T07:16:55.816876 #30] INFO -- : 文言`のような形式
          - `30`はプロセスID
      - 環境ごとにログのレベルを指定するのが普通
        - `Logger::Severity`の定数で指定できる
      - ログを吐く場所の指定もする(stdout, file等を指定)
  - たとえばRailsのログ用gemのLogrageは、json形式のフォーマッターは`::JSON.dump(data)`で定義している
    - https://github.com/roidrage/lograge/blob/master/lib/lograge/formatters/json.rb
