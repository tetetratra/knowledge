# 記事の分割ルール

- 書籍のメモは1冊につき1ページとし、章・節・話題ごとには分割しない。技術同人誌も同様に扱う。

- 1記事は、単独で読み返せる1つの技術的な話題を扱う。
- 元記事を最初から細切れにせず、独立した複数の話題がある場合だけ分割する。短い用語説明、単一の手順、同じ主題の参考リンク一覧はそのまま残す。
- 箇条書きの親子、前提と結論、コードと説明、表、画像と説明は同じ記事に置く。「前述」「上記」などの参照が宙に浮く分割はしない。
- 各記事の先頭に内容を表す `# タイトル` を1つ置く。元の章名だけでは主題が分からないときは技術名を補う。
- 分割時に新たな技術的主張・説明・出典を追加しない。原文の条件、不確実性、数値、コードを保ち、必要な共通の前提と出典だけを各記事に引き継ぐ。
- frontmatterは `tags: "タグ1, タグ2"` のみ。冒頭のタグと内部リンク先の技術用語をタグに含め、本文の内部リンクはプレーンテキストとする。公開著者・登壇者の情報は保持し、私的な人物名・個人ページ・個人アイコンはタグにも残さない。
- ファイルはすべて `notes/` 直下へ置き、画像は `assets/` の物理ファイルを相対参照する。
- 変換結果・分割結果を原文と照合し、欠落や意味変更がないか確認する。
- 分割判断、匿名化、画像確認に迷うページは無理に処理せず保留とする。保留理由を記録し、ユーザーの判断を待つ。
- 元の1ページを複数記事へ分割する変更を、1コミットにまとめる。1対1移行はその前の独立したコミットとして残す。
